!!! DEFECT FOUND (test-only constraint prevented a fix) !!!
  ConcurrentSubmissionIT proved check-then-act idempotency races: two
  concurrent submits of the SAME key both call the PAID bureau endpoint
  (PRD: never twice for one submission), and the loser's insert throws
  JpaSystemException — SQLite reports UNIQUE violations as
  JpaSystemException, NOT DataIntegrityViolationException, so the
  saveIdempotently catch never fires -> HTTP 500 instead of dedupe.
  Test left @Disabled with the defect documented + suggested fix
  (key-scoped lock + catch JpaSystemException/DataAccessException).
